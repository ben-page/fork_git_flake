# Wine patches

Patches applied on top of nixpkgs' Wine (`wineWow64Packages.unstable`). They are generated with
`git format-patch` from a Wine tree.

or later. The rest of this repository is MIT-licensed (see `LICENSE`).

| Patch | What it fixes |
|-------|---------------|
| `0001-combase-tests-Add-tests-for-RoGetParameterizedTypeIn.patch` | Conformance tests for `RoGetParameterizedTypeInstanceIID` (marked `todo_wine`) |
| `0002-combase-Implement-RoGetParameterizedTypeInstanceIID.patch` | Implements `RoGetParameterizedTypeInstanceIID`, a stub in Wine. .NET Framework calls it to marshal generic WinRT types; without it Fork dies at start-up with `E_NOTIMPL` when it subscribes to `UISettings.ColorValuesChanged` |
| `0003-uxtheme-tests-Check-the-color-and-size-names-GetCurr.patch` | Conformance test: with Aero, `GetCurrentThemeName()` reports the color scheme `NormalColor` (marked `todo_wine`) |
| `0004-aero.msstyles-Name-the-color-scheme-NormalColor-like.patch` | Names Wine's Aero color scheme `NormalColor`, as Windows does, instead of `Blue`. WPF builds its theme dictionary's name from it (`themes/aero2.normalcolor`) and otherwise falls back to its Classic theme |
| `0005-winewayland-Release-the-mouse-button-after-starting-.patch` | Sends a window the mouse button release once the compositor has taken over a move or resize, since the compositor keeps the real one. Without it, Fork showed the no-drop cursor after a title-bar drag and ignored drags until the next click |
| `0006-winewayland-Let-resizable-windows-be-resized-from-ju.patch` | Gives resizable windows an invisible border 8 units wide just outside their edges, where the pointer shows resize cursors and a press starts a compositor resize, as with other Wayland windows. Fork draws its own frame, so before this it could only be resized from a few pixels inside its edge. Whether the pointer is on the border is decided from its position, because KWin keeps reporting the pointer on whichever surface it was on after a move or resize |
| `0007-dwrite-Reuse-a-face-s-FreeType-sizes-instead-of-crea.patch` | Keeps a font's FreeType sizes for reuse instead of creating one for every glyph DirectWrite measures or draws. Creating a size runs a hinted font's setup programs, so with hinted Inter, Fork took about half a second to redraw at each new size while being resized, and switching to a large repository's tab blocked it for 0.6-1.4 s; with the patch, about a fifth of a second for both |
| `0008-winewayland-Scroll-with-touchpads.patch` | Scrolls with touchpads. They send only continuous scrolling, which Wine's Wayland driver ignored, so two-finger scrolling did nothing. Every 15 units of it, what libinput reports for a wheel click, now becomes a wheel step: whole steps, because WPF scrolls three lines per wheel message whatever its size |
| `0009-winewayland-Implement-support-for-rotated-displays.patch` | Wine's pending merge request 8647 (Etaash Mathamsetty, July 2025), unchanged. Swaps a display mode's width and height when the compositor reports the output rotated by 90 or 270 degrees. Wine's Wayland driver ignored the rotation and took a portrait monitor for a landscape one, and Wine limits a window's drawing buffer to the screen it knows, so on a portrait monitor a window taller than the monitor's width got a buffer shorter than itself; the compositor stretched that buffer to fill the window, and clicks landed on the real layout rather than on the picture |
| `0010-win32u-Keep-the-host-position-of-displays-that-repor.patch` | Keeps the position the driver gives a display that reports a single mode. Wine built that display's settings from the bare mode, which has no position, so on KWin, which reports one mode per output, every monitor was placed at (0,0), on top of the others |
| `0011-win32u-Open-the-link-itself-when-creating-a-key-with.patch` | Opens a registry link key itself when win32u asks for it with `REG_OPTION_OPEN_LINK`, as `RegCreateKeyEx` does. Wine repoints each display source's registry link at the current source this way, but the request followed the link and wrote into the old source instead, so the links kept pointing at the first outputs Wine saw. After monitors came back under new names, as after a resume or a dock reconnect, one of them lost its source and Wine reported a 1024x768 primary monitor at (0,0) in its place |
| `0012-server-Reset-an-unclipped-cursor-rectangle-when-the-.patch` | Has wineserver recompute the pointer's limits whenever the monitors change, unless an application set its own. It only did that when the desktop window was resized or another window came to the front, so limits taken while a monitor was briefly reported as 1024x768 could outlast it, and Wine's Wayland driver kept the pointer inside that box |
